# AI 문체 패턴 카탈로그

사용 지침 세 가지. 단일 신호는 증거가 아니다(사람도 "다양한"을 쓴다). 여러 신호가 한 글에 뭉쳐 나오는 것이 티다. 목록은 모델 세대별로 변한다("delve"는 2023~24년 GPT-4 시대의 티였고 이후 급감). 새 패턴을 발견하면 이 파일에 추가한다. 아래 "고침" 예시는 기본 방향일 뿐이며, 글쓴이의 실제 목소리와 글의 맥락이 항상 우선한다.

단 하나의 예외: **em dash(—)는 신호의 강약과 무관하게 절대 금지**다(SKILL.md 하드 규칙). 이것만은 뭉침 여부를 따지지 않고 무조건 제거한다.

## A. 한국어: 번역투 (한국어 AI 글의 최대 신호원)

| 패턴 | 예 → 고침 |
|---|---|
| "~을/를 통해" | "회의를 통해 결정했다" → "회의에서 정했다" |
| "~에 있어(서)" | "글쓰기에 있어 중요한 것은" → "글 쓸 때 중요한 것은" |
| 이중 피동 "~되어지다" | "사용되어진다" → "쓰인다" |
| "~을 가지고 있다" | "장점을 가지고 있다" → "장점이 있다" |
| 무생물 주어 + 사역 | "이 도구는 시간을 단축시켜 준다" → "이 도구를 쓰면 시간이 준다" |
| "그/그녀" 반복 | 이름·직함으로 바꾸거나 생략 (한국어는 주어를 생략하는 언어) |
| "~에 대해/대한" 남용 | "성능에 대한 개선" → "성능 개선" |
| 명사화 남용 | "검토를 진행하다" → "검토하다" |
| '의' 중첩 | "작업의 상황의 기록" → "작업이 진행된 상황을 적은 기록" (K 참조) |

## B. 한국어: 어미·쉼표·띄어쓰기 (형태론 층위, 판별력 가장 높음)

- 종결어미 단조: "~습니다" 또는 "~다"가 3문장 이상 연속. "~거든요", "~인 셈이다", 명사형 마무리 등으로 변주.
- 영어식 쉼표: 주어 뒤, 접속사 앞, 연결어미 뒤("~했는데, ~해서,")의 쉼표. 한국어는 원래 쉼표를 덜 쓴다. 연결어미 뒤 쉼표는 AI가 인간의 약 4.8배(KatFish 분석). **쉼표는 한국어 AI의 최강 단일 신호다.** 쉼표 특징만으로 에세이 판별 AUC 94.88%(KatFishNet). LLM은 사람의 약 2배 문장에 쉼표를 넣고 문장 뒤쪽에 배치한다. 목표는 문장당 쉼표 1개 이하, 특히 연결어미 뒤 쉼표를 없앤다(문두 접속부사 뒤 쉼표처럼 글쓴이의 습관인 것은 예외로 존중한다).
- 지나치게 완벽하고 균일한 띄어쓰기. 사람 글엔 자연스러운 변동이 있다.

## C. 한국어: 어휘·구조 표지

- 빈 수식어: 다양한, 핵심적인, 필수적인, 혁신적인, 획기적인, 효과적으로, 성공적으로, 전략적으로
- 구조 표지: "지금부터 ~을 살펴보겠습니다" / "첫째, 둘째, 셋째" / "결론적으로, 요약하자면, 마치며" 뒤 앞 내용 재진술
- 확장 구문: "~뿐만 아니라 ~도"
- 문두 접속사 남발: 또한, 아울러, 더욱이, 이와 더불어, 게다가. 지워도 문맥이 이어지면 지운다(대부분 이어진다).
- 교사 모드·과잉 아첨: "쉽게 말해 ~라고 이해하시면 됩니다", "정말 핵심을 찌르는 질문이에요"

## D. 공통: 구문·수사 (한국어·영어 모두)

- 부정 병치: "단순한 X가 아니라 Y다" / "It's not just X, it's Y". 한 번은 수사, 글 전체에서 반복되면 티.
- 3박자 나열(rule of three): "빠르고, 정확하고, 안전하다" 강박. 하나를 빼거나 4개로.
- 현재분사 꼬리: "..., ~을 보여주며 ~의 중요성을 시사한다" / "..., highlighting the significance of..."
- 의의 부풀리기: "중요한 전환점", "더 큰 흐름의 일부", "marking a pivotal moment"
- 익명 권위: "전문가들은", "업계에서는", "Experts argue". 이름과 출처를 대거나 지운다.
- 헤징 스택: "어느 정도 도움이 될 수 있을 것으로 보인다". 헤지는 하나만.
- 뻔한 결론 공식: "물론 과제도 남아 있다 → 그럼에도 전망은 밝다"
- 수사적 질문 던지고 바로 자답하기

## E. 공통: 구두점·서식

- **em dash(—): 절대 금지, 예외 없음** (SKILL.md 하드 규칙). 공백 두른 형태( — )와 대시 용도의 en dash(–)도 포함. 쉼표·괄호·콜론으로 바꾸거나 문장을 나눈다. 출력 전 `—` 검색으로 0건 확인.
- 이모지 헤더·불릿 (✅ 🚀 💡), 볼드 남용, 개조식 강박 (산문으로 충분한 내용을 목록화)
- 유니코드 화살표: "기획 → 개발 → 배포"
- 짧은 글의 소제목 과잉, 모든 레벨에서 재요약하는 프랙탈 구조
- 챗봇 잔재: "도움이 되었길 바랍니다!", 인용 마커 찌꺼기(oaicite 등)

## F. 영어 글 전용: 어휘

- 2023~24 세대 (여전히 잔존): delve, tapestry, pivotal, underscore, testament, showcase, intricate, meticulous, vibrant, crucial, garner, foster, realm, landscape(추상명사), Additionally(문두)
- 최근 세대: emphasizing, enhance, highlighting, showcasing 계열
- 축약형(contractions) 전무 = 딱딱한 티. it's, don't를 자연스럽게 쓴다.

## G. 한국어: 표제·제목 (탈문장성)

제목·목차·파트·소제목·헤딩·캡션은 **본문 서술과 다른 층위**다. 한국어 표제는 명사·명사구·명사형(`~하기`, `~법`), 질문형, 청유(`~하자/~하라`), 계사(`~이다`)로 닫힌다. 완결 평서 종결(`~ㄴ다/~는다/동사 어간+다`)로 끝내면 제목이 라벨이 아니라 **본문에서 떨어져 나온 한 문장(캡션)**으로 읽혀 번역투 신호가 된다(영어 명령형 헤딩 Build/Ship/Sell의 직역). 신문 헤드라인이 "규제 완화"이지 "규제를 완화한다"가 아닌 것과 같은 원리.

| 패턴 | 예 → 고침 |
|---|---|
| 동사 평서 종결 표제 | "안전하게 지킨다" → "안전하게 지키기 / 지키는 법" |
| 목적어 없이 매달린 타동사 표제 | "무너지지 않게 만든다"(무엇을?) → "무너지지 않게 만들기 / 무너지지 않는 구조" |
| 표제 안 등위 쉼표(영어 and 직역) | "팔고, 붙잡는다" → "팔기와 붙잡기 / 판매와 유지" |

- **층위 가드**: A의 "명사화 남용 감축"(`검토를 진행하다` → `검토하다`)은 **본문 서술에만** 적용한다. 표제에서는 오히려 명사형이 정답이다. 교정 전에 대상이 표제인지 본문인지 먼저 분기한다.
- 한 문서 안에서 표제 종결 톤을 통일한다(명사형이면 명사형끼리, 질문형이면 질문형끼리).

## H. 한국어: 연어·의미중복

- **연어(collocation) 오류**: 서술어는 관습적으로 어울리는 주어·목적어가 있다. 문법이 맞아도 관습 밖 조합이면 어색하다. 판단 기준은 "문법적으로 맞나"가 아니라 "이 조합이 실제로 함께 쓰이나".
  - '무너지다'는 [쌓여 서 있던 구조물·조직·질서·계획·마음](건물, 세력, 왕조, 기강, 방어선)에 붙는다. **코드·빌드·결과물·데이터·UI엔 안 붙는다.** → 깨지다(빌드·테스트·레이아웃), 터지다(에러·예외), 뻗다·죽다(서버·프로세스), 망가지다. 예: "코드가 무너진다" → "코드가 깨진다 / 뻗는다".
  - (참고: 서비스·시스템 같은 대규모 인프라는 조직 은유로 '무너지다'가 부분 허용. 작은 산출물 단위엔 부자연.)
- **영어 구동사 직역 은유**: falls apart / break down / keep safe / take into account를 직역하면 연어 위반. "무너지지 않게(코드)"←falls apart, "고려에 넣다"←take into account, "안전하게 지키다"←keep safe. → 한국어 자연 연어로.
- **겹말(의미 중복)**: 수식어가 서술어에 이미 든 의미 성분을 되풀이하면 삭제. '지키다'엔 [보호·방어·안전 유지]가 내포돼 "안전하게 지키다"는 겹말. 같은 유형: 박수를 치다, 상을 수상하다, 공감을 느끼다, 미리 예약, 그대로 답습, 계속 속출, 다시 재계약, 역전 앞. **예외**: 새 정보(시간·주체·정도)를 더하는 수식은 정당("끝까지 지키다", "혼자서 지키다").

## I. 한국어: 통사 (타동사 논항·병렬)

- **타동사 목적어는 필수 논항**이다. 한국어가 목적어를 자주 생략하지만, 그건 앞 문맥에 지시 대상이 있어 "무엇을?"이 복원될 때만 자연스럽다. 표제·구호·버튼은 선행 문맥이 없어 목적어를 밝히거나 명사구화해야 한다. "안전하게 지킨다"(무엇을?) → 목적어 복원 또는 명사형.
- **등위접속 병렬은 공유 논항을 요구**한다. 목적어가 다른 두 타동사를 "A하고 B한다"로 묶으면 붕괴한다. "제품을 팔고 / 고객을 붙잡고"를 "팔고 붙잡는다"로 압축하면 뒤 동사의 빈 목적어가 앞의 '제품'으로 오복원된다("제품을 붙잡는다"?). → 목적어를 각각 명시하거나 문장을 분리. 목적어가 같을 때만 압축 병렬이 자연스럽다("자산을 지키고 불린다").
- **영어 무목적어 동사 병렬(sell and retain, build and ship)은 직역 불가**. 명사화("판매와 유지"), 목적어 각각 채우기("제품을 팔고 고객을 붙잡는다"), 공유 목적어 재구성("앱을 만들어 배포한다") 중 하나로.

## J. 한국어: 수·나열·라벨의 영어 직역

한국어와 영어는 수를 세고 항목을 늘어놓는 방식이 다르다. 영어 구조를 그대로 옮기면 문법은 맞는데 번역서를 읽는 느낌이 남는다. 표제와 문단 첫머리에서 특히 티가 크다.

| 패턴 | 예 → 고침 |
|---|---|
| `N개의 X`(영어 of 구문 직역) | "세 개의 장면" → "세 장면 / 무슨 일이 있었나", "네 개의 항목" → "항목 네 가지" |
| 나열 라벨 이식(Scene One / Case 1) | "장면 하나. 2025년 7월, ..." → "2025년 7월, ..." |
| 수 표기를 한글로 풀어쓰기 | "오 분 뒤" → "5분 뒤", "열 배" → "10배", "서른 번" → "30번" |
| 전문용어 복합어 축자 번역 | code freeze → "코드 동결"(원어를 아는 사람만 읽힘) → "코드는 건드리지 말라고 못 박아 둔 상태" |

- **`N개의 X`**: 한국어는 수량사를 명사 뒤에 두거나(항목 네 개) 수식을 줄인다(세 장면). 영어 어순을 살리려고 '개의'를 끼우는 순간 번역투가 된다. 표제에서는 수를 빼고 내용어로 바꾸는 편이 낫다.
- **나열 라벨**: 영어 논픽션은 "Scene One / Case 1 / Exhibit A"로 문단을 연다. 한국어 산문은 시간·장소·사실로 바로 들어간다("2일 전, 세 사람을 만났다"). 문단 나눔이 이미 구분자라 라벨은 대개 군더더기다.
- **수 표기**: 시간·수량·배수·횟수는 아라비아 숫자로 쓴다. 한글로 풀면 번역서 문어체가 된다. **예외 둘**: 관용 표현과 어림수는 한글을 유지하고("열 번 중 아홉 번", "한두 번", "수천 명"), 낭독용 원고는 입으로 읽는 기준을 따른다("백 명이든 만 명이든").
- **전문용어**: 영어 복합어를 축자 번역하면 원어를 아는 사람만 읽는 말이 된다. 독자가 비전문가면 풀어 쓰거나, 원어를 병기하고 뜻을 문장으로 설명한다.

## K. 한국어: 생략·압축 (전보문체)

한국어 AI 문체의 두 번째 축이다. A~J가 잘못 더한 것을 걷어내는 규칙이라면 K는 부당하게 뺀 것을 되돌리는 규칙이다. 토큰을 아끼도록 조율된 모델에서 특히 심하게 나타나며, 조사와 어미, 서술어, 의미를 담은 문장 성분이 빠지고 명사만 남아 전보문이 된다. 금지어가 하나도 없는 문장이라 A~J의 목록으로는 걸리지 않는다.

| 패턴 | 예 → 고침 |
|---|---|
| 조사·어미 생략 | "컨텍스트 압축 전 신중 반영한다" → "컨텍스트가 압축되기 전에 신중히 반영한다" |
| 의미 성분 생략 | "그러면 경고가 붙는다" → "그러면 이미 작업 중인 파일에도 경고 표지가 붙는다" |
| '의' 사슬로 관계 뭉개기 | "사본의 문구는 작업의 상황을" → "사본에 적힌 문구는 작업이 진행되는 상황을" |
| 명사구 압축 | "지출 비용 추론 용도의 토큰 카운트 함수의 오류 상황에서" → "지출한 비용을 추론하는 토큰 카운트 함수에 오류가 발생하면" |
| 서술어 없는 판정 | "이 결정은 중요 정책이 갈리는 자리." → "이 결정은 이후 정책에 계속 영향을 준다." |

- **판단 기준은 복원 가능성이다.** 빠진 성분이 앞 문맥에서 "무엇이 무엇을?"으로 복원되면 한국어가 원래 하는 생략이므로 손대지 않는다. 복원되지 않으면 관계가 사라진 압축이므로 되돌린다. 문장이 짧다는 것 자체는 근거가 아니다.
- **'의' 검문**: 한 문장에 '의'가 두 번 이상 나오면 그 자리마다 관형절이나 서술어로 풀 수 있는지 본다. 명사 둘을 '의'로 붙이는 순간 둘 사이의 관계(주체·대상·수단·소속)가 사라져서 독자가 추측하게 된다.
- **복원 수단은 조사와 어미만이 아니다.** 부사, 보조사, 선어말어미, 보조 용언을 쓰면 시점과 태도까지 함께 들어온다.
- 맥락에 맞는 한자어를 고르고 거기에 조사와 어미를 붙이면 짧으면서도 관계가 분명한 문장이 된다. 다만 원문이 쓰고 있는 구어와 음차 어휘를 한자어로 바꾸지는 않는다.
- **의도된 생략과 구분한다.** 문단 끝의 단문, 조각문 여운("어차피 정답은 없으니."), 이유로 끝내는 문장은 글쓴이가 택한 리듬이다. K로 풀면 원칙 3의 리듬 변주와 정면으로 충돌하고 목소리가 뭉개진다. K가 잡는 것은 문체가 아니라 사고가 압축되면서 관계가 사라진 문장이다.

## L. 한국어: 뜻이 비는 낱말

A~K가 문장 구조를 보는 규칙이라면 L은 낱말 하나를 본다. 구조가 멀쩡한데도 읽고 나서 남는 것이 없는 문장은 대개 이 네 갈래 중 하나다. 낱말을 바꾸는 것으로 끝나지 않고, **그 자리에 원래 들어갔어야 할 구체가 무엇인지**를 같이 묻는다.

| 갈래 | 예 → 고침 |
|---|---|
| 모호한 형용사 | "기억이 흐린 부분", "흐릿한 기준" → "기억나지 않는 부분", "확실하지 않은 기준" |
| 자리를 가리키는 빈 명사 | "이 결정이 갈리는 자리", "설정을 두는 판", "검증 쪽에서 막는다" → "이 결정이 나뉘는 지점", "설정을 두는 파일", "검증 단계에서 막는다" |
| 뻔한 은유 | "복원 지점을 세이브 포인트라고 부른다", "이 검사가 관문이다", "설정이 열쇠다" → 은유를 빼고 그 일을 하는 말로: "복원 지점", "이 검사를 통과해야 다음으로 간다", "이 설정이 판단 근거다" |
| 독자를 겁주는 말 | "겁먹지 마세요", "당황하지 마세요", "걱정하지 마세요" → 겁을 준 뒤 달래지 말고 사실만: "여기서 막히는 경우가 많습니다", "이 화면이 나와도 정상입니다" |

- **모호한 형용사**: '흐린·흐릿한·막연한'처럼 정도를 가리키는 말은 독자마다 다르게 읽는다. 무엇이 어떻게 부족한지를 쓴다.
- **빈 명사**: '자리·판·쪽·곳'은 위치를 가리키는 듯하지만 실제 위치를 말하지 않는다. 파일인지 단계인지 화면인지 영역인지 이름을 부른다. K의 '서술어 없는 판정'과 짝이다.
- **뻔한 은유**: 설명글에서 은유는 개념을 처음 세울 때 한 번만 값어치가 있다. 두 번째부터는 정확한 이름을 가린다. 특히 '열쇠·심장·관문·문·방'처럼 누구나 떠올리는 은유는 그 자체가 예측 가능한 선택이라 D의 상투구와 같은 신호다.
- **겁주는 말**: AI 글은 독자가 불안해할 것을 먼저 가정하고 달래는 문장을 넣는 습관이 있다. 그 문장은 정보가 없고, 없던 불안을 만들어 낸다. 사실을 말하고 넘어간다.
- 이 절은 낱말 목록이 아니라 갈래다. 같은 낱말도 뜻이 살아 있으면 그대로 둔다("바닥에 깐다", "왼쪽 화면").
